# Music Mode Machine Learning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Music mode hears singing versus speech with Apple's on-device classifier, records the owner's listening for training, and recognises sections with a small trained model that beats the hand-written rules, with tempo and key trackers tuned on public benchmarks and everything written up in `docs/research.md`.

**Architecture:** The Swift helper gains an optional SoundAnalysis classifier whose results travel on file descriptor 3 beside the PCM stream. A recorder saves listening sessions (FLAC, local) with feature logs and moments the owner marks through Claude. Offline tools turn the SSME dataset into per-second feature sequences, score the rules, train an MLP with scikit-learn (dev only) and export numpy weights that the Analyzer uses at runtime under the existing state machine.

**Tech Stack:** Swift / SoundAnalysis, Python 3.12, numpy (runtime), scikit-learn and scipy (dev only), ffmpeg (decode and FLAC encode).

**Spec:** `docs/superpowers/specs/2026-10-26-music-mode-design.md`, section "Revision 2: machine learning" and the decisions after it. Builds on plans `2026-10-26-music-mode.md` and `2026-10-26-music-understanding.md`.

## Global Constraints

- No audio is committed. Datasets live in `~/datasets`; the owner's recordings and labels in `CONFIG_DIR` (`~/.config/amaran-mcp`). Every audio and label path is outside the repository.
- The published model (`src/amaran_mcp/music/sections.npz`) is trained only on public data (SSME, Creative Commons) and synthetic arrangements. A model that also uses the owner's recordings is written to `CONFIG_DIR / "sections.npz"` and preferred at runtime when present. The write-up names the shows but not the owner's individual clips.
- scikit-learn and scipy are dev dependencies only (`uv add --dev`); runtime inference is numpy.
- The model ships only if, on held-out SSME tracks split by track, it beats the rules on frame accuracy and on build and break boundaries within 2 s, and is no worse than the rules on the owner's labelled clips (reported separately).
- The state machine stays on top of the model: the model proposes section probabilities; the state machine enforces order and minimum durations; the rules are the fallback when the model is absent or its top probability is below 0.5.
- Recording never deletes anything automatically: it stops recording at a size cap (default 30 GB) and says so in the status.
- Singing (or choir) confidence drives the vocal reading; it is held down while speech is above 0.5. Microphone fallback keeps the heuristic estimate.
- Anti-goals and slew limits unchanged. No em-dashes or emojis in files.

## Review Focus

1. The classifier is unavailable (older macOS, or the helper built without it): music mode runs on the heuristic vocal estimate, with no error loop. (Task 1 test)
2. A host talking over an intro while a sung vocal sample plays underneath: speech above 0.5 holds the vocal down; once speech stops, singing comes through. (Task 2 test)
3. Recording hits the size cap mid-session: recording stops, music mode keeps running, the status says why. (Task 3 test)
4. A marked moment arrives while music mode is not recording (or not running): the tool says so instead of writing an orphan label. (Task 3 test)
5. An SSME track whose .mat file is missing a field or has unequal start/end arrays: the loader skips that event with a warning, the track still counts. (Task 4 test)

### Task 1: Classifier in the helper, read on fd 3

**Interfaces:**
- Produces: helper flag `--classify`; fd 3 JSON lines `{"t": float, "singing": p, "choir_singing": p, "speech": p, "rapping": p, "cheering": p, "crowd": p, "applause": p}` about every 0.5 s (window 1.5 s, overlap 0.66). `SystemAudio(classify: bool = True)` exposes `latest_classes() -> dict[str, float] | None` (None until the first line, or when fd 3 is closed or the helper lacks the flag).
- Steps: (1) test with a fake helper (Python) that writes RATE + PCM on stdout and two JSON lines on fd 3, asserting `latest_classes()` returns the second; test that a helper exiting with "unknown flag" on `--classify` is retried without it and `latest_classes()` stays None. (2) watch fail. (3) Swift: `SNAudioStreamAnalyzer` fed from the IOProc's mono buffer (copied to an `AVAudioPCMBuffer` on a serial queue, never blocking the IOProc), observer writing to fd 3. Python: open the helper with `pass_fds` on a pipe, read lines in a task. (4) pass. (5) Live check: `say -v "Good News" "la la la la la"` (a singing voice) and plain `say` (speech) while running `amaran-mcp music-probe --classify 8`; expected singing above 0.5 for the first and speech above 0.5 for the second. Record both results in the ledger. (6) commit.

### Task 2: Vocal reading from the classifier

**Interfaces:**
- Consumes: `latest_classes()`.
- Produces: `Analyzer.feed(samples, classes: dict | None = None)`; `Timbre` gains `singing: float | None`, `speech: float | None`; `Features.timbre.vocal` = `max(singing, choir_singing)` eased (rise 0.7 s, fall 1.5 s), multiplied by `max(0, 1 - 2 * max(0, speech - 0.5))` when classes are present; the heuristic otherwise. The runner passes `source.latest_classes()` when the source has it.
- Tests: classes with singing 0.9, speech 0.1 give vocal above 0.7 after 3 s; singing 0.9 with speech 0.9 gives vocal below 0.2; classes None keeps the heuristic (existing timbre tests unchanged).

### Task 3: Recording the owner's listening, and marking moments

**Interfaces:**
- Produces: `recorder.Recorder(directory, cap_bytes=30 * 2**30)` with `write(block, rate)`, `mark(kind, note=None) -> dict`, `close()`; writes `CONFIG_DIR/recordings/<start>/audio.flac` (ffmpeg, 24 kHz mono, new file every 30 min as `audio-NNN.flac`), `features.jsonl` (the runner's feature log, always on while recording), `marks.json` (`[{"t": seconds_since_start, "kind": ..., "note": ...}]`). Kinds: breakdown, lift, vocal, build, drop, other.
- `RunnerConfig.record: bool = True`; `control.start(mood, record=True)`; MCP `start_music_mode(mood, record=True)`; new MCP tool `mark_music_moment(kind, note=None)` that writes through a control file the runner reads each second (mark time = when the runner reads it minus nothing: the tool writes the wall clock time; the runner converts it to recording time).
- Tests: a recorder fed 70 s of fixture audio with a 30 s segment length writes three FLAC segments that decode to the same total length; a cap smaller than one segment stops recording and sets a status message; `mark` before any audio raises; the MCP tool returns "music mode is not recording" when no session is running.

### Task 4: SSME dataset loader

**Interfaces:**
- Produces: `tools/ssme.py` with `unpack(root)` (joins the split zip with `zip -s 0` into a temp file and extracts it, once), `labels(mat_path, duration) -> list[dict]` in the label format (`{"start", "end", "section"}`; break to breakdown, build to build, drop to a release event plus climax from the drop for 32 bars at the track's tempo, or 30 s; everything else groove), `tracks(root) -> list[(audio_path, labels)]`.
- Tests: a synthetic .mat written with scipy (two builds, one break, one drop) converts to the expected segments; unequal start/end arrays skip that event with a warning (Review Focus 5); a missing field yields no events of that kind.

### Task 5: Features, rules baseline, scoring

**Interfaces:**
- Produces: `tools/extract_features.py ROOT --out ~/datasets/features/<set>/` writing one `.npz` per track: per-second vectors (the `sections.FEATURES` list: energy, bass, kick, pulse, onset_jump, tension, openness, balance, harmony confidence, chord changes per 8 s, vocal, singing, speech, level_db) plus the rules' section per second. `sections.FEATURES` and `sections.window(vectors, i) -> np.ndarray` (16 s context: means, last minus first, std) live in `src/amaran_mcp/music/sections.py` so training and runtime share them.
- `tools/score_sections.py` reports frame accuracy and boundary precision, recall and F (within 2 s) per section, and release-event F (within 2 s of SSME drops), for the rules and, when given, a model.
- Tests: `window` on a synthetic sequence has the documented length and values; scoring a perfect prediction gives 1.0; a prediction shifted by 3 s fails the 2 s boundary test.

### Task 6: Train, gate, ship, integrate

**Interfaces:**
- Produces: `tools/train_sections.py --features DIR [--owner] [--out PATH]`: 5-fold cross-validation by track, MLP (32, 32), class weights balanced; prints rules versus model per fold and pooled; refuses to write unless the gate in Global Constraints passes. Weights format: `{"means", "scales", "W0", "b0", "W1", "b1", "W2", "b2", "classes"}`.
- Runtime: `sections.Model.load(path) -> Model | None`, `Model.proba(window) -> dict[str, float]`; `Analyzer` keeps the last 16 s of feature vectors, asks the model each second, and the state machine switches section only to the model's top section when its probability is at least 0.5 and the transition is allowed (intro to groove; groove to breakdown or build; breakdown to build or climax via release; build to climax via release; climax to groove or breakdown); otherwise the rules decide.
- Tests: numpy inference equals scikit-learn `predict_proba` on random inputs to 1e-6; with a stub model that always says "breakdown" at 0.9, a groove still cannot jump to climax; with no model file the Analyzer behaves exactly as before (all existing analysis tests pass unchanged).

### Task 7: Benchmarks and tuning

- Run `tools/benchmark_tempo.py` and `tools/benchmark_key.py` on the full sets. Tune `tempo.CONFIDENT` (candidates 0.2 to 0.4) for best Accuracy 1 on 100 to 150 BPM tracks without false locks on the synthetic pads test; tune chroma confidence similarly. Replace `test_blend_of_two_tempos_drops_confidence` with `test_blend_reports_one_of_the_two_tempos` if the new threshold no longer separates the synthetic blend. Re-check the owner's ASOT clip replay (breakdown still found by 1:40). Record before and after tables.

### Task 8: Owner model, history, write-up, publish

- With the owner's recordings and marks: `tools/train_sections.py --owner --out ~/.config/amaran-mcp/sections.npz` (local only).
- Listening history: if the owner allows Terminal to control Music, export library play dates and counts (AppleScript, read-only) to `CONFIG_DIR/history.json` and summarise artists and genres in the write-up in aggregate only; if they sign in to music.apple.com in Chrome, read Replay the same way. Apple's full history export (privacy.apple.com) is the owner's to request.
